# Практическое задание №1. Эмулятор командной строки

**Дисциплина:** Конфигурационное управление  
**Вариант:** №24  
**Язык:** Python 3.9+  
**Интерфейс:** командная строка (CLI)  
**Зависимости:** только стандартная библиотека Python

## Общее описание

Программа имитирует работу командной строки UNIX. Пользователь вводит команды в интерактивном режиме, а эмулятор выполняет их над **виртуальной файловой системой (VFS)**, которая загружается из JSON. Файлы компьютера не изменяются: команда `touch` работает только с данными в оперативной памяти.

Выполнены пять этапов задания. История Git содержит ровно **пять коммитов**. Для просмотра версий есть ветки `etap-1` … `etap-5` и теги `etap-1` … `etap-5`. Дополнительное требование по флагам `ls -l`, `ls -a`, `ls -h` и их сочетаниям включено в этап 4.

## Установка и запуск

Нужно установить Python 3.9 или новее. Сторонние библиотеки не нужны. Откройте терминал в папке проекта и выполните:

```bash
python -m src.main --vfs vfs/nested.json
```

На Windows при необходимости вместо `python` используйте `py`. Также можно запустить `run.bat --vfs vfs/nested.json`.

Для выполнения команд из файла:

```bash
python -m src.main --vfs vfs/nested.json --script scripts/demo.txt
```

Для демонстрации флагов `ls`:

```bash
python -m src.main --vfs vfs/nested.json --script scripts/ls_flags.txt
```

Для запуска без файла VFS (пустая виртуальная система):

```bash
python -m src.main
```

### Параметры запуска

| Параметр | Назначение |
|---|---|
| `--vfs ПУТЬ` | Загрузить виртуальную файловую систему из JSON |
| `--script ПУТЬ` | Прочитать команды из текстового файла и выполнить по порядку |
| `--help` | Показать справку о параметрах запуска |

Если стартовый скрипт содержит ошибку, выполнение **останавливается на первой ошибке**. В интерактивном режиме после ошибки можно вводить следующую команду.

## Команды и настройки

| Команда | Поведение |
|---|---|
| `ls [путь]` | Выводит имена файлов и каталогов; по умолчанию скрытые имена не показывает |
| `ls -l [путь]` | Выводит подробный список с условными правами, владельцем и размером |
| `ls -a [путь]` | Показывает скрытые имена, `.` и `..` |
| `ls -h [путь]` | Показывает размер в удобных единицах **при наличии `-l`** |
| `ls -lah [путь]` | Одновременно применяет `-l`, `-a`, `-h` (порядок флагов не важен) |
| `cd [путь]` | Переходит в виртуальный каталог; без аргумента — в корень `/` |
| `find [путь]` | Рекурсивно выводит пути ко всем вложенным элементам |
| `tail [-n N] файл` | Выводит последние 10 строк текстового файла или последние N строк |
| `cal [месяц год]` | Выводит календарь текущего либо указанного месяца |
| `touch файл` | Создаёт пустой файл в виртуальной системе, не меняя исходный JSON |
| `exit` | Завершает работу эмулятора |

Допустимы сочетания `ls -la`, `ls -lh`, `ls -ah`, `ls -alh`, `ls -hla`, `ls -l -a -h` и другие комбинации этих трёх флагов. Неверный флаг вызывает ошибку.

**Примечание:** JSON VFS не хранит реальные права доступа, владельца и дату изменения, поэтому в `ls -l` эти данные условные. Размер файла вычисляется по декодированному содержимому; каталогам соответствует размер 0.

## Формат виртуальной файловой системы

Каталог имеет тип `dir` и поле `children`; файл имеет тип `file` и поле `content`, в котором текст хранится в кодировке base64. Пример:

```json
{
  "type": "dir",
  "children": {
    "note.txt": {
      "type": "file",
      "content": "SGVsbG8K"
    }
  }
}
```

Этот пример описывает каталог `/` с файлом `note.txt`, содержащим строку `Hello` и перевод строки. Поддерживаются абсолютные и относительные пути, а также имена с пробелами в кавычках.

## Интерактивная демонстрация

Ввести команды по одной, подтверждая Enter:

| Ввод | Ожидаемое поведение |
|---|---|
| `ls` | Показывает `hello.txt` и `home` в корне `nested.json` |
| `cd home/student/docs` | Переходит в `/home/student/docs` |
| `ls` | Показывает `report.txt` |
| `tail -n 2 report.txt` | Выводит последние две строки файла |
| `cal 10 2026` | Показывает календарь октября 2026 года |
| `touch "new file.txt"` | Создаёт виртуальный файл с пробелом в имени |
| `ls -lah` | Показывает подробный список, включая скрытые имена и размеры |
| `find /home` | Выводит вложенные пути от `/home` |
| `exit` | Завершает сеанс |

### Проверка ошибок

| Ввод | Результат |
|---|---|
| `unknown` | Ошибка неизвестной команды |
| `ls a b` | Ошибка количества аргументов |
| `ls -z` | Ошибка неизвестного флага |
| `cd missing` | Ошибка отсутствующего пути |
| `tail /` | Ошибка: требуется файл |
| `cal 13 2026` | Ошибка некорректной даты |
| `cd "` | Ошибка незакрытых кавычек |
| `exit now` | Ошибка количества аргументов; сеанс не завершается |

После ошибки интерактивная командная строка продолжает работать. Пустая строка ничего не выполняет.

### Публикация в GitHub

Создайте пустой репозиторий **без автоматического README и .gitignore**. Откройте терминал в распакованной папке, где уже лежит `.git`:

```bash
git remote add origin https://github.com/USERNAME/config-management-24.git
git push -u origin main
git push origin --tags
git push origin etap-1 etap-2 etap-3 etap-4 etap-5
```

Замените `USERNAME` на свой логин GitHub. Если `origin` уже существует, проверьте `git remote -v` и при необходимости используйте `git remote set-url origin НОВЫЙ_URL`. **Не запускайте `git init` и не делайте `git add .` / `git commit`**, иначе история будет отличаться от подготовленной.

На GitHub ветка `main` показывает готовый этап 5. Через переключатель веток можно открыть любой `etap-N`, а через историю коммитов увидеть пять последовательных версий.
